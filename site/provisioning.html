Hand a phone its configuration.

Type your target below and this page makes two things: a dshbyok://setup link, and a QR code for it. Scan the code or open the link on the phone, and the app shows what it would change and waits for you to confirm.

Generated in your browser

Nothing here is sent anywhere. There is no analytics, no font, no script from another host — the page draws the QR code with a vendored encoder (qr.js, MIT). The address field is prefilled from the URL fragment (the part after #), which browsers never transmit, so a link to this page cannot leak the address it carries to this site or to anyone watching the network.

The link

dshbyok://setup

Any camera or QR app will open it: the scheme is dshbyok, so Android asks which app should handle it. Nothing installs and nothing changes until the app itself applies it.

What a link may say — and what it may never say#

Configuration only

A link may carry: target, port, scheme, path, mode, update, control, node. The app shows the merged result before applying it, and refuses a link whose target its address policy would not let you type by hand.

Never a credential

If a link contains any field whose name looks like a credential — authkey, key, token, password, secret — the whole link is refused, and the app says so. A link can be photographed off a screen, so a secret in one is a secret in public. The auth key is typed into the app, or obtained through the control plane's own login.

Never silent

A link cannot re-point the app by itself. That is the attack worth designing against — a QR code that quietly aims the app at a stranger's server, so the next thing you type is your key. The app therefore parses, shows, and waits: apply or ignore is your tap.

Baking a target into your own build#

The public build carries no address, on purpose. A private or branded build can pre-fill one, and then nobody has to type anything: 

./gradlew assembleDebug -PdefaultTarget=phone.tailnet-name.ts.net:3080 -PdefaultMode=system

The value only *defaults* the first screen — it is never a policy, and once the user saves anything the stored value wins. Those properties are also run through the same parser a link is, so a malformed value degrades to "no default" rather than shipping a broken address. Nothing is committed: the public build's values are empty, and CI checks that they stay that way.

More detail, including the full field table and the reasoning: docs/PROVISIONING.md.
