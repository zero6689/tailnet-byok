Architecture

Four layers, one seam that matters, and a short list of popular libraries that are deliberately absent.

The shape#

ui/setup Compose screen + view model │ domain/ConnectionTester the six-step test domain/TailnetAddressPolicy what may be dialled, and why not │ net/ConnectivityProvider ← the seam ╱ ╲ net/SystemNetworkProvider net/tsnet/TsnetConnectivityProvider (plain sockets) (embedded node, gomobile bridge) │ tailnet/tailnet.go (Go, tsnet)

The one seam that matters is ConnectivityProvider. The UI never branches on which implementation is active; it reads a status flow and calls start/probe/fetch. That is what makes the embedded node genuinely optional — the default build simply has no implementation registered for it, and the UI says so instead of crashing — and what would make a third provider (a different mesh, a relay, a mock for tests) a local change.

LayerPackageResponsibility
UI ui/setup, ui/theme Compose screen, one UiState, one view model. No business rules.
Domain domain What may be dialled, and the ordered test. Pure Kotlin: no Android types, so it is testable on the JVM without Robolectric.
Network net, net/tsnet Two ways to reach the target, behind one interface.
Data data/config, data/crypto Persistence, and the Keystore-backed vault.
Native tailnet/ (Go) The embedded node, and the only code that talks to the control plane.

Why the HTTP happens in Go#

This is the least obvious decision in the codebase, so it is worth stating.

The socket has to be created by the tailnet's own network stack — that is what makes the traffic go through the tunnel. But a Go net.Conn has no Java representation, so no JNI binding can hand it back. The options were:

  1. run a SOCKS5 proxy on loopback and have OkHttp dial through it;
  2. give the Go side a request-shaped API and return the response bytes.

Option 2 was chosen. It removes a listening socket from the process, removes a credential for that proxy, and keeps the whole path in one place. The cost is that HTTP lives in two implementations rather than one — which is a real cost, and the reason ConnectivityProvider.fetch() takes a request object rather than exposing a client.

The binding rules#

tailnet/tailnet.go follows one rule: every exported function takes and returns only String, Int, Bool or error. Structured data crosses as JSON; byte payloads are base64 inside that JSON.

That is not stylistic. gomobile cannot express a Go interface or a net.Conn, and multi-value returns bind differently across gomobile revisions. Keeping the surface primitive means the generated Java is stable, reviewable, and independent of the binding generator's mood.

Why one provider is loaded reflectively#

TsnetConnectivityProvider compiles against classes that only exist after gomobile bind. The default build — a fresh clone, and CI without a Go toolchain — has no such classes. A direct reference from shared code would break the build for everyone who is not shipping the native bridge.

ProviderRegistry therefore resolves the installer with Class.forName and a single install method, only when BuildConfig.TSNET_ENABLED is true. A separate Gradle module per provider does not remove the problem — the consumer still has to name the class — it only moves the failure.

Consequence

R8 cannot see the reference, so app/proguard-rules.pro keeps **.net.tsnet.** explicitly. Without that rule the failure is release-only and presents as "the embedded node feature silently disappeared" — the worst kind of bug to chase. If you add a provider, add its keep rule too.

What is deliberately not there#

No Hilt

Four objects, one scope. A framework would add an annotation processor, a plugin, a generated component, and a second way to construct every object — to remove four lines of wiring in AppContainer.kt that a reader can follow at a glance.

This is a judgement, not a principle. Add a background component or a second graph and the trade flips; the wiring is in one file precisely so the swap is one file.

No Retrofit

The app makes one kind of request to exactly one host, and it has to go through the provider seam anyway. Retrofit's value is managing a large typed API surface; there is no such surface here.

No Room

Eleven scalar preferences in DataStore. A relational store would be ceremony around a key-value workload.

No navigation library

One screen. Adding a back stack to a single destination is a graph with one node.

No Timber

One fewer dependency to audit in the code path that handles the credential. SafeLog is forty lines and does the redaction Timber would not.

No analytics, no crash reporter

Not a cost decision. A crash reporter is a network destination that sees your configuration, and this app's whole claim is that it has no such destination.

State and lifetime#

Three rules, each with a reason:

  • The plaintext key is never part of UiState. It lives in keyDraft only while being typed, is written to the vault on save, and is read back only for the duration of a connection test. So a state dump, a test assertion, or a screenshot cannot contain it — the state object holds a boolean, hasStoredKey.
  • The object graph is owned by Application. The root composable reads it from the application context rather than receiving it, which makes a configuration change structurally unable to produce a second graph — and therefore a second embedded node fighting over one state directory.
  • One provider instance per ProviderId, created on first request. Nothing eagerly loads the native library, so a build with the bridge in which the user never enables it pays nothing at cold start.

Why src/tsnet is a separate source set

app/build.gradle.kts adds src/tsnet/kotlin to the main source set only when -PwithTsnet=true and app/libs/tailnet.aar exists. If the property is set and the AAR is missing, the build fails immediately with the command to produce it — rather than with the ten thousand lines of "unresolved reference: mobile" that a naive configuration produces.

Known gaps

Listed so that they are not discovered by you:

GapImpact
No instrumented tests Anything needing a real device — Keystore behaviour, the native bridge — is verified by hand, not by CI.
UI strings are not extracted The app cannot be translated without moving copy out of the Compose sources into resources. This is a deliberate trade: each warning currently sits next to the condition that triggers it.
Per-ABI AAR size is unmeasured An embedded tsnet node adds a Go runtime. It is not small, and abiFilters is not configured.
No reproducible-build guarantee Release APKs are signed in CI but not verified bit-for-bit reproducible.
The bridge is compiled, not audited tsnet is a large dependency. This project neither vendors nor reviews it.

Extending it

A third provider, in four steps:

  1. Add a value to ProviderId.
  2. Implement ConnectivityProvider.
  3. Register it in ProviderRegistry.initialise().
  4. If it needs a heavy dependency, put it in its own source set and add a Class.forName hook plus a ProGuard keep rule — the pattern tsnet uses.

No UI change is required. The provider selector is driven by ProviderId.entries and the registry's availability list.
