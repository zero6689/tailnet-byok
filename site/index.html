Overview Build & use Security Architecture

An Android app that carries its own Tailscale node.

Paste a pre-auth key and a target host. The app joins your tailnet, on your terms, and talks to that one service. No account with us, no server of ours, no shared relay — and no VPN permission.

What "BYOK" means here

The key is a Tailscale auth key, not an LLM API key. It is stored encrypted by the Android Keystore, it is never written to disk in plain text, it is never logged, and it leaves the device only to reach the control plane you configure.

Why this exists#

Reaching a service on your own tailnet from a phone normally means one of two unsatisfying options.

The official Tailscale app

It works, and for most people it is the right answer. But it takes the device-wide VPN slot, changes DNS for every app on the phone, and — decisively — no other app can hand it an auth key. There is no API, intent or content provider for that.

So if your goal is "an app that provisions a device onto my tailnet from inside the app", this route cannot do it. Not "is inconvenient" — cannot.

Ship your own VPN service

That means BIND_VPN_SERVICE, a foreground service, split-tunnel policy and a permanent notification — a great deal of surface, and a great many ways to get it wrong, in order to open one socket to one host.

Most of that surface exists to serve the case where you want to route everything. This app does not.

tailnet-byok takes a third path: it embeds a userspace Tailscale node with tsnet and dials the target through it. The device's other traffic is untouched. No VPN permission is requested. The app opens one connection, to one destination, and nothing else.

The shape is borrowed from two projects that proved it works: tailvisor (tsnet without a system VPN) and netbirdio/android-client (a gomobile-bound tunnel inside a Kotlin app), applied to the single-destination case.

What it does#

FeatureHow
Configuration Auth key, target host (MagicDNS name or 100.x address), port, scheme, path, node hostname, and an optional self-hosted control server for headscale.
Secure storage AES-256-GCM under a key that lives in the Android Keystore. On a device with a TEE or StrongBox, that key never exists in the app's address space at all.
Connection test Six named steps, each with a duration, stopping at the first hard failure. It tells you which part broke, because the fixes are different.
Direct connection Traffic reaches the target over the tailnet, from inside the app, through the tailnet's own network stack.

A sample run#

✓ Validate target address target looks like a tailnet address ✓ Select connection method using Embedded tailnet node ✓ Check stored credential auth key present (fp:3f9a1c04) ✓ Bring up tailnet node node up at 100.101.102.103 1840 ms ✓ Open TCP connection connected in 142 ms (resolved to 100.101.102.103) 142 ms ✓ Send HTTP request HTTP 200 187 ms Connected

Note what is not in that output: the auth key. The credential step reports a non-reversible fingerprint (fp:3f9a1c04) — enough to tell two keys apart in a log, useless for anything else.

And when it fails, it says which part:

✗ Validate target address a public address is not reachable through a tailnet. Use the 100.x address or the MagicDNS name.

Security posture, in one table#

RequirementHow it is met
No hardcoded private configuration No credential exists in the source, the build, or BuildConfig. The only generated constant is a non-secret control-plane URL.
Key never on disk in plain text AES-256-GCM via the Android Keystore, setRandomizedEncryptionRequired, setUnlockedDeviceRequired on API 28+. Node state lives in noBackupFilesDir.
Key never in a log One logging entry point, scrubbed; release builds strip v/d/i at the bytecode level; CI fails the build on a bare android.util.Log call.
No accidental egress Anything outside 100.64.0.0/10, fd7a:115c:a1e0::/48 and named hosts is refused before a dial — in the network layer, not just in the UI.
Nothing leaves the device allowBackup="false", backup rules exclude everything, no analytics, no crash reporter, no server of ours.
Minimum permissions Three: INTERNET, ACCESS_NETWORK_STATE, POST_NOTIFICATIONS. No BIND_VPN_SERVICE, no QUERY_ALL_PACKAGES, no location.
Read this before trusting it with a key

The honest limits are documented rather than glossed over — including the fact that the plaintext key exists in the heap for a short window, because Kotlin strings cannot be zeroed. See Security.
