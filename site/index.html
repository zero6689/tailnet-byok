An Android client for one service on your own tailnet.连你自己 tailnet 里那一个服务的 Android 客户端。

You bring the network and the server. Paste a target host, sign in, and the app talks to that one service. No account with us, no server of ours, no shared relay — and the app itself asks for no VPN permission. This app does not provide a tailnet, a node, or a relay: the day-to-day path is the system network, where the tunnel belongs to the official Tailscale app, and the optional embedded-node mode dials from inside the app with your own Tailscale auth key.网络和服务器都由你提供。粘贴目标主机、登录，App 就只与那一个服务通信。 不需要在我们这里注册账号，没有我们的服务器，没有共享中继 —— App 自身也不申请 VPN 权限。 本项目不提供 tailnet、不提供节点、也不做中继：日常使用的是系统网络模式，隧道由官方 Tailscale 应用提供；可选的「内嵌节点」模式才在 App 进程内拨号，用的是你自己的 Tailscale 认证密钥。

What "BYOK" means here这里的“BYOK”是什么意思

The key is a Tailscale auth key, not an LLM API key. It is stored encrypted by the Android Keystore, it is never written to disk in plain text, it is never logged, and it leaves the device only to reach the control plane you configure.这里的密钥是 Tailscale 认证密钥，不是 LLM API key。它由 Android Keystore 加密保存，绝不会以明文写入磁盘，绝不会进日志，只有当它前往你配置的控制面时才会离开设备。

Why this exists为什么会有这个项目#

Reaching a service on your own tailnet from a phone normally means one of two unsatisfying options.在手机上访问自己 tailnet 里的某个服务，通常只有两个都不太令人满意的选择。

The official Tailscale app官方的 Tailscale App

It works, and for most people it is the right answer. But it takes the device-wide VPN slot, changes DNS for every app on the phone, and — decisively — no other app can hand it an auth key. There is no API, intent or content provider for that.它确实能用，对大多数人来说也是正确答案。但它占用了设备级的 VPN 槽位，会改动手机上 每个 App 的 DNS，而且最关键的是：没有别的 App 能把手里的认证密钥交给它。 没有为此提供 API、intent 或 content provider。

So if your goal is "an app that provisions a device onto my tailnet from inside the app", this route cannot do it. Not "is inconvenient" — cannot.所以如果你的目标是「一个能在自己的 App 里把设备配置进我的 tailnet 的 App」， 这条路走不通。不是「不方便」，而是走不通。

Ship your own VPN service自己实现一个 VPN 服务

That means BIND_VPN_SERVICE, a foreground service, split-tunnel policy and a permanent notification — a great deal of surface, and a great many ways to get it wrong, in order to open one socket to one host.这意味着 BIND_VPN_SERVICE、前台服务、拆分隧道策略和一条常驻通知 —— 为了打开一个到单个主机的套接字，要引入一大片攻击面，还要面对大量出错的可能。

Most of that surface exists to serve the case where you want to route everything. This app does not.这一大片东西，大多是为了服务「想路由所有流量」的场景。这个 App 不做那件事。

tailnet-byok takes a third path: it embeds a userspace Tailscale node with tsnet and dials the target through it. The device's other traffic is untouched, and the app itself asks for no VPN permission — on the system-network path the tunnel belongs to the official app instead. The app opens one connection, to one destination, and nothing else.tailnet-byok 走了第三条路：它用 tsnet 内嵌了一个用户态的 Tailscale 节点，并通过它拨号到目标。设备上的其它流量完全不受影响，App 自身也不申请 VPN 权限 —— 走系统网络模式时，隧道由官方应用提供。 这个 App 只打开一条连接、只连一个目的地，别的什么都不做。

That third path is why the project exists and it is optional: the same build also runs on the device's existing network, which is the mode used day to day and the one that needs no auth key. Nothing here is a service you sign up for — the network and the server are yours.这「第三条路」是本项目存在的理由，但它是可选的： 同一个安装包也能直接走设备现有网络，那才是日常使用的模式，而且不需要任何认证密钥。 这里没有需要注册的服务 —— 网络和服务器都是你自己的。

The shape is borrowed from two projects that proved it works: tailvisor (tsnet without a system VPN) and netbirdio/android-client (a gomobile-bound tunnel inside a Kotlin app), applied to the single-destination case.这个形态借鉴了两个已经证明它可行的项目： tailvisor（不带系统 VPN 的 tsnet）和 netbirdio/android-client （Kotlin App 里由 gomobile 绑定的隧道），并把它们用在「单一目的地」这一场景上。

What it does它能做什么#

Feature能力How实现方式
Configuration配置 Auth key, target host (MagicDNS name or 100.x address), port, scheme, path, node hostname, and an optional self-hosted control server for headscale.认证密钥、目标主机（MagicDNS 名称或 100.x 地址）、端口、 scheme、path、节点主机名，以及可选的、供 headscale 使用的自建控制服务器。
Secure storage安全存储 AES-256-GCM under a key that lives in the Android Keystore. On a device with a TEE or StrongBox, that key never exists in the app's address space at all.AES-256-GCM 加密，密钥存放在 Android Keystore 中。在带 TEE 或 StrongBox 的设备上， 这把密钥根本不会出现在 App 的地址空间里。
Connection test连接测试 Six named steps, each with a duration, stopping at the first hard failure. It tells you which part broke, because the fixes are different.六个具名步骤，每步都有耗时，遇到第一个硬失败就停下。它会告诉你哪一步 坏了，因为各自的修法并不相同。
Direct connection直连 Traffic reaches the target over the tailnet, from inside the app, through the tailnet's own network stack.流量在 App 内部经由 tailnet 自己的网络栈到达目标。

Security posture, in one table一张表看安全姿态#

Requirement要求How it is met如何满足
No hardcoded private configuration没有硬编码的私有配置 No credential exists in the source, the build, or BuildConfig. The only generated constant is a non-secret control-plane URL.源码、构建产物和 BuildConfig 里都不存在任何凭据。 唯一生成的常量是一个非机密的控制面 URL。
Key never on disk in plain text密钥绝不以明文落盘 AES-256-GCM via the Android Keystore, setRandomizedEncryptionRequired, setUnlockedDeviceRequired on API 28+. Node state lives in noBackupFilesDir.通过 Android Keystore 使用 AES-256-GCM，在 API 28+ 上启用 setRandomizedEncryptionRequired、setUnlockedDeviceRequired。 节点状态存放在 noBackupFilesDir。
Key never in a log密钥绝不进日志 One logging entry point, scrubbed; release builds strip v/d/i at the bytecode level; CI fails the build on a bare android.util.Log call.只有一个日志入口，并且会做脱敏；release 构建在字节码层面剔除 v/d/i； CI 一旦发现裸的 android.util.Log 调用就让构建失败。
No accidental egress不会意外外联 Anything outside 100.64.0.0/10, fd7a:115c:a1e0::/48 and named hosts is refused before a dial — in the network layer, not just in the UI.任何不在 100.64.0.0/10、fd7a:115c:a1e0::/48 和具名主机范围内的目标，都会在拨号之前被拒绝 —— 在网络层拒绝，而不只是在 UI 上。
Nothing leaves the device什么都不离开设备 allowBackup="false", backup rules exclude everything, no analytics, no crash reporter, no server of ours.allowBackup="false"，备份规则排除一切，没有统计，没有崩溃上报， 也没有我们的服务器。
Minimum permissions最小权限 Six, and one of them only while you are watching a task: INTERNET, ACCESS_NETWORK_STATE, POST_NOTIFICATIONS, REQUEST_INSTALL_PACKAGES (the updater asks the system installer; it cannot install silently), CAMERA — asked for by the QR scanner screen alone, and optional, because a code can be read from a picture instead — and FOREGROUND_SERVICE, so a task you started can be noticed finishing while the app is off screen. No BIND_VPN_SERVICE, no QUERY_ALL_PACKAGES, no location.六个，其中一个是「只在你在等任务跑完时」才用到的：INTERNET、 ACCESS_NETWORK_STATE、POST_NOTIFICATIONS、 REQUEST_INSTALL_PACKAGES（更新时交给系统安装器，无法静默安装）、 CAMERA —— 只由二维码扫描页申请，而且是可选的：不改用相机也能用图片识别 —— 以及 FOREGROUND_SERVICE：让你启动的任务在 App 退到后台后跑完也能被发现。没有 BIND_VPN_SERVICE，没有 QUERY_ALL_PACKAGES，不读位置。
Read this before trusting it with a key在把密钥交给它之前，请先读这一节

The honest limits are documented rather than glossed over — including the fact that the plaintext key exists in the heap for a short window, because Kotlin strings cannot be zeroed. See Security.诚实的局限是被写进文档的，而不是被含糊带过 —— 包括明文密钥会在堆上短暂存在这一 事实，因为 Kotlin 字符串无法被清零。见安全。
