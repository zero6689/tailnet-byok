Build & use

Two build modes. One needs JDK 17 and an Android SDK; the other additionally needs Go, gomobile and the NDK, and gives you the embedded node.

The honest summary

A fresh clone builds and runs without Go. It will tell you the embedded provider is not compiled in and offer the system-network fallback. If the whole point for you is the auth-key field, you need the second mode — and about two gigabytes of toolchain, which one script will fetch.

Fast path#

git clone {{REPO_URL}}.git
cd {{REPO_NAME}}

node scripts/fetch-toolchain.mjs gradle sdk   # Gradle + Android SDK, if you lack them
node scripts/make-wrapper.mjs                 # generates gradlew / gradlew.bat

./gradlew assembleDebug                        # macOS / Linux
.\gradlew.bat assembleDebug                    # Windows

That produces an APK in app/build/outputs/apk/debug/. It runs, and the embedded provider will be reported as unavailable — with the reason shown in the UI rather than as a crash.

Full build, with the embedded node#

node scripts/fetch-toolchain.mjs go ndk   # Go + Android NDK
node scripts/build-bridge.mjs             # gomobile bind -> app/libs/tailnet.aar

./gradlew assembleDebug -PwithTsnet=true

scripts/build-bridge.mjs --check reports the toolchain it can see without building anything, which is the fastest way to find out what is missing.

Why the AAR is not committed#

Because there is no prebuilt one to commit. Neither tailscale/libtailscale (which is a C library, and produces no Android artifact at all) nor tailscale/tailscale-android (whose GitHub releases ship only APKs) publishes one on Maven Central or JitPack. The AAR has to be built from source, which is what the script does.

Why not just reuse Tailscale's AAR?#

Two reasons, and the second is the important one.

  1. It does not expose what this app needs. The binding has no typed Dial and no GetIP; all control flows through a local HTTP API over JNI.
  2. Using it commits you to the system VPN slot. Its Kotlin side implements IPNService (a VpnService) and an AppContext; the Go side calls back into them. You would be building the official app's architecture — device-wide routing, split-tunnel policy, a foreground service — to open one socket.

So this project binds tsnet directly, with a deliberately tiny surface: every exported Go function takes and returns only String, Int, Bool or error. Structured data crosses as JSON. That avoids both the interface-binding problem (a Go net.Conn has no Java representation) and the version sensitivity of multi-value returns.

Install them from the same golang.org/x/mobile revision. Different revisions produce bindings that describe an ABI the runtime library does not implement, and the failure appears at the first call rather than at build time — which is a genuinely miserable thing to debug. build-bridge.mjs installs both from one --gomobile-version, and prints the resolved versions so you can pin them.

SDK level overrides#

The default is compileSdk 35 / targetSdk 35, which is what a Play submission needs. If your local SDK is older, override both: 

./gradlew assembleDebug -PcompileSdk=34 -PtargetSdk=34

Note that AndroidX 1.15+ requires compileSdk 35, so this override is only useful if you also lower the dependency versions in gradle/libs.versions.toml.

Using it#

1. Create a pre-auth key#

In your tailnet's admin console: Settings → Keys → Generate auth key.

  • Prefer single-use: one device, one key.
  • Prefer a tag (for example tag:phone) so your ACLs can grant that tag access to exactly the service you intend.
  • Set an expiry you will actually notice.

The app cannot enforce any of that for you. It is the difference between a key that is a credential and a key that is a capability.

2. Enter the target host#

Accepted forms, in order of how likely they are to just work:

InputVerdictNotes
100.101.102.103:3080 best No DNS in the path. If this fails, the network is wrong, not the resolver.
host.tailnet.ts.net:3080 good MagicDNS FQDN. Resolved by the node's own network stack.
100.101.102.103 warns Port defaults to 3080, and the app says so.
myhost warns A bare short name needs the tailnet search domain. An embedded node is not guaranteed to have it. Use the FQDN or the IP if this fails.
http://100.101.102.103:3080 refused Drop the scheme; there is a separate selector for it.
93.184.216.34 refused A public address is not reachable through a tailnet. This is a security boundary, not a UX preference.
127.0.0.1 refused That is the phone, not your server.

3. Test#

The button runs six checks and stops at the first hard failure. Read the first ✗ — that is the thing to fix. Everything below it is marked skipped rather than failed, because a skipped step tells you nothing.

Using headscale instead of Tailscale#

Fill in the Control server field with your headscale base URL, for example https://headscale.example.com, and create the pre-auth key with headscale rather than Tailscale: 

headscale preauthkeys create --user <USER_ID>
headscale preauthkeys create --tags tag:phone --expiration 1h

Leaving the field empty means Tailscale's hosted control plane. Note that passing that hosted URL explicitly is not the same as leaving it empty — tsnet treats a non-empty value as a custom server. The app normalises this for you.

Trap

tsnet ignores the auth key you supply when usable node state already exists on disk, unless TSNET_FORCE_LOGIN=1 is set. This produces the single most confusing symptom in the whole project: "I pasted a new key and nothing changed."

The app handles it: Forget key and reset node clears both the stored ciphertext and the node's state directory, and the Go bridge exposes an explicit forceLogin parameter.

Troubleshooting#

SymptomCause and fix
"not compiled into this build" You built without the bridge. Run scripts/build-bridge.mjs, then rebuild with -PwithTsnet=true.
"no native library for this device ABI" The AAR is present but lacks your ABI — usually an x86_64 emulator with an arm64-only build. Rebind without trimming ABIs.
Node starts, TCP times out Usually the port, or a service that is not listening. "Connection refused" means the host answered; "timed out" means it did not.
MagicDNS name does not resolve Use the 100.x address. Bare short names are the least reliable form; even full FQDNs depend on the control plane having published the suffix.
"the encryption key was invalidated" The device's lock screen or credentials changed, which destroys Keystore keys. Re-enter the auth key. This is expected behaviour, not a bug.
Auth key rejected Check the key's tags against your ACLs, and that it has not expired. A key from Tailscale will not work against headscale, or the reverse.
Diagnostics

The Diagnostics button shows the provider, whether the Keystore key is hardware-backed, the node's state and address, the target with the host partially masked, and the tailnet node's own recent log lines — all redacted before display.
